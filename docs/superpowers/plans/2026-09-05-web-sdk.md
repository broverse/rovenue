# Web SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@rovenue/web-sdk` — a TypeScript SDK that reads entitlements, serves placements, records events and starts Stripe checkouts from a browser — plus the two server capabilities it needs and that do not exist today.

**Architecture:** The `/v1` surface already serves the native SDKs and is reused unchanged. Two server gaps are closed first: browser access (allowed origins declared on the API key, with the project resolvable from a parameterised URL prefix so a credential-less CORS preflight can be answered) and `POST /v1/checkout` (a Stripe Checkout Session whose security shape mirrors `/v1/billing-portal`). The client is three layers — a framework-agnostic core, a thin React layer, and a binding that feeds the existing `@rovenue/paywall-renderer`.

**Tech Stack:** Hono + Zod + Drizzle (API), Stripe Checkout Sessions, TypeScript (strict), Vitest, React 18, pnpm workspaces, tsup or equivalent for dual ESM/CJS output.

**Spec:** `docs/superpowers/specs/2026-09-05-web-sdk-design.md`

## Global Constraints

- **Stay on the current branch (`main`).** Never create or switch branches, never create a worktree. A concurrent human author commits to this branch; never `--amend`, `reset --hard`, `rebase`, or force anything, and commit with explicit pathspecs.
- **No magic values.** Repeated literals become named constants. Structured data tables are data, not magic values.
- **TypeScript strict everywhere; Zod for API input; every response is `{ data: T }` or `{ error: { code, message } }`.**
- **Postgres via Drizzle only**, repositories under `packages/db/src/drizzle/repositories`. In raw `sql`, qualify columns (`"api_keys"."id"`) — a bare `${table.col}` renders unqualified and breaks correlated subqueries.
- **The outbox is the only path to Kafka.** Never write a domain table and Kafka in one code path.
- Exact values: header names `x-rovenue-app-user-id`, `x-rovenue-platform` (from `HEADER` in `@rovenue/shared`); SDK platform for this client is `"web"` (already a valid `SDK_PLATFORMS` member); browser mount prefix `/v1/web/:publicKey`; package name `@rovenue/web-sdk` at `packages/sdk-web`, version `0.16.0` to stay aligned with the other five SDK packages.
- **CORS is not an authorization boundary.** Do not write code or comments implying it is. Authorization rests on the unguessable `rovenueId`, project scoping, rate limits and key revocation.
- **Verification runs against real behaviour.** Preflight assertions issue real `OPTIONS` requests; race assertions run real concurrent calls against a testcontainer Postgres. A test that would pass without the mechanism existing proves nothing.
- Tests: Vitest. `*.integration.test.ts` use testcontainers. Throttle: `nice -n 19 npx vitest run --maxWorkers=2`; never run the full monorepo suite when a filtered run will do.
- Conventional commits, one per task.

- [ ] **Step 3: Write the middleware**

`apps/api/src/middleware/browser-cors.ts`:

```typescript
import type { MiddlewareHandler } from "hono";
import { cors } from "hono/cors";
import { HEADER } from "@rovenue/shared";

// Per-key CORS for the browser surface.
//
// A CORS preflight is an OPTIONS request with NO Authorization header, so
// the server cannot know which project is asking from the Bearer key at the
// moment it must decide the origin. That is the entire reason the public key
// is in the URL: it is the only project reference a preflight can carry.
//
// This middleware MUST be mounted on the parameterised prefix
// (`/v1/web/:publicKey/*`), not on `app.use("*")` — a route param is not
// available to app-level middleware, so the key would read as undefined and
// every origin would be refused.
//
// CORS is not an authorization boundary: a non-browser client ignores it.
// What it prevents is another website's JavaScript using this key inside a
// visitor's browser. Authorization rests on the unguessable rovenueId, the
// project scoping of the key, rate limits and revocation.
export const browserCors = (
  lookupAllowedOrigins: (publicKey: string) => Promise<string[]>,
): MiddlewareHandler =>
  async (c, next) =>
    cors({
      origin: async (origin) => {
        const publicKey = c.req.param("publicKey");
        if (!publicKey) return null;
        const allowed = await lookupAllowedOrigins(publicKey);
        // Exact match only — scheme, host and port.
        return allowed.includes(origin) ? origin : null;
      },
      allowMethods: ["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"],
      allowHeaders: [
        "Content-Type",
        "Authorization",
        "Idempotency-Key",
        HEADER.X_ROVENUE_APP_USER_ID,
        HEADER.X_ROVENUE_PLATFORM,
      ],
      exposeHeaders: [
        "X-Request-Id",
        HEADER.X_RATE_LIMIT_LIMIT,
        HEADER.X_RATE_LIMIT_REMAINING,
        "Retry-After",
      ],
      credentials: false,
      maxAge: 86400,
    })(c, next);
```

`credentials: false` is deliberate: the SDK sends a Bearer key and an app-user header, never cookies, and `credentials: true` alongside a reflected origin is the combination that turns a CORS mistake into a session-riding one.

- [ ] **Step 4: Mount it**

In `apps/api/src/app.ts`, after the existing `/v1` mount, add the browser surface. The lookup is a cached read of the key's `allowedOrigins`; reuse whatever cache the API key auth path already uses rather than adding a second one.

```typescript

    .route("/v1/web/:publicKey", v1Route)
```

Order matters: the middleware must be registered before the route.

### Task 8: Entitlement cache that survives having no browser

**Files:**
- Create: `packages/sdk-web/src/storage.ts`, `packages/sdk-web/src/cache.ts`
- Test: `packages/sdk-web/src/storage.test.ts`, `packages/sdk-web/src/cache.ssr.test.ts`

**Interfaces:**
- Consumes: the core client (Task 7)
- Produces: `getEntitlements({ fromCache })` returning last-known entitlements offline, and a storage abstraction the event queue (Task 9) reuses.

- [ ] **Step 1: Write the failing tests**

The SSR test is the one that matters — Next.js and Remix execute this code on a server with no `localStorage`, and a module-scope access throws at import time, before any consumer can guard it.

```typescript
// @vitest-environment node
it("imports and constructs with no DOM at all", async () => {
  expect(typeof globalThis.localStorage).toBe("undefined");
  const { configure } = await import("../index");
  const sdk = configure({ apiKey: PK, apiUrl: API });
  expect(sdk).toBeDefined();
});

it("falls back to an in-memory cache when storage is unavailable", async () => {
  const store = createStorage();
  store.set("k", "v");
  expect(store.get("k")).toBe("v");
});

it("keeps working when localStorage throws", () => {
  vi.stubGlobal("localStorage", { getItem() { throw new Error("blocked"); }, setItem() { throw new Error("blocked"); } });
  const store = createStorage();
  expect(() => store.set("k", "v")).not.toThrow();
  expect(store.get("k")).toBe("v");
});
```

The third case is real: private-browsing modes and cookie-blocking settings make `localStorage` *present but throwing*, which a `typeof` check does not catch.

- [ ] **Step 2: Run to verify they fail**

Run: `nice -n 19 npx vitest run --maxWorkers=2 packages/sdk-web/src/storage.test.ts packages/sdk-web/src/cache.ssr.test.ts`
Expected: FAIL.

- [ ] **Step 3: Implement**

`createStorage()` probes `localStorage` inside a `try/catch` on first use — never at module scope — and returns an in-memory implementation when it is missing or throws. The cache stores the last entitlement response with a fetched-at timestamp and serves it when the network fails.

Nothing in the package may touch `window`, `document` or `localStorage` at module scope. This is what the SSR test enforces.

- [ ] **Step 4: Run the tests**

Run: `nice -n 19 npx vitest run --maxWorkers=2 packages/sdk-web`
Expected: PASS.

- [ ] **Step 5: Commit**

```bash
git add packages/sdk-web/src
git commit -m "feat(sdk-web): entitlement cache with a storage fallback

localStorage can be absent (SSR) or present-but-throwing (private mode,
blocked cookies) — a typeof check catches only the first. Probed in a
try/catch on first use, never at module scope, so importing the SDK on a
server does not throw."
```

### Task 9: An event queue that survives the tab closing

**Files:**
- Create: `packages/sdk-web/src/events.ts`
- Test: `packages/sdk-web/src/events.test.ts`

**Interfaces:**
- Consumes: storage (Task 8), the core client (Task 7)
- Produces: `track(event)` with at-least-once delivery.

"At-least-once" is a claim, not a design, unless the flush path handles unload.

- [ ] **Step 1: Write the failing tests**

```typescript
it("flushes with sendBeacon when the page hides", () => {
  const beacon = vi.fn(() => true);
  vi.stubGlobal("navigator", { sendBeacon: beacon });
  const q = createEventQueue(deps);
  q.track({ name: "paywall_view" });
  document.dispatchEvent(new Event("visibilitychange"));
  expect(beacon).toHaveBeenCalledTimes(1);
});

it("falls back to keepalive fetch when sendBeacon is unavailable", () => { /* ... */ });

it("retains events that failed to send and replays them next session", async () => {
  const q = createEventQueue({ ...deps, post: () => Promise.reject(new Error("offline")) });
  q.track({ name: "paywall_view" });
  await q.flush();
  const next = createEventQueue(deps);
  await next.flush();
  expect(deps.post).toHaveBeenCalledWith(expect.arrayContaining([expect.objectContaining({ name: "paywall_view" })]));
});

it("deletes an event only after a 2xx", async () => { /* peek → post → delete-on-2xx */ });
```

The last two encode the rule the native SDKs already follow: peek, post, delete only on success. Deleting before the response turns a network blip into lost telemetry.

- [ ] **Step 2: Run to verify they fail**

Run: `nice -n 19 npx vitest run --maxWorkers=2 packages/sdk-web/src/events.test.ts`
Expected: FAIL.

- [ ] **Step 3: Implement**

Queue in storage; flush on a timer, on `visibilitychange → hidden` and on `pagehide`; `navigator.sendBeacon` first, `fetch(..., { keepalive: true })` as fallback. Events carry a deterministic id so the server's existing dedup makes replay safe.

- [ ] **Step 4: Run the tests**

Run: `nice -n 19 npx vitest run --maxWorkers=2 packages/sdk-web`
Expected: PASS.

- [ ] **Step 5: Commit**

```bash

git commit -m "feat(sdk-web): at-least-once event queue with unload flush

Peek, post, delete only on 2xx — the rule the native SDKs already follow.
Flushes via sendBeacon on visibilitychange and pagehide, because a timer
```
