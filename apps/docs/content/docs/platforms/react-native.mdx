<Callout type="warn">
The code on this page is verified against `@rovenue/react-native-sdk`'s
actual exported surface (`examples/sample-rn-expo` typechecks against it),
but that example app cannot currently be Metro-bundled or run on a
device/simulator in this monorepo — two dependency-hoisting mismatches
between the app's pinned Expo/React Native versions and the SDK's peer
range break both CocoaPods and Metro before any app code runs. If you hit
similar resolution errors in your own app, pin `expo`/`react-native` to
versions inside the SDK's declared peer range rather than assuming your
`App.tsx` is the problem.
</Callout>

<Steps>

<Step>
### Install the package

Install with your package manager (your choice is remembered across the whole site):

```package-install
@rovenue/react-native-sdk
```

**Expo managed workflow** — add the config plugin to `app.json` (or `app.config.js`). It auto-wires the iOS CocoaPods dependency and Android Gradle on prebuild:

```json
{
  "expo": {
    "plugins": ["@rovenue/react-native-sdk"]
  }
}
```

Then run:

```bash
npx expo prebuild
```

**Bare React Native** — after installing, run pod install for iOS:

```bash
cd ios && pod install
```

> Supported platforms: iOS 16.0+ (device and simulator).

<Callout type="info">
Peer dependencies: `expo >=51 <53`, `expo-modules-core`, `react >=18`, `react-native >=0.73`.
</Callout>
</Step>

<Step>
### Configure the SDK

Call `Rovenue.configure` once at the root of your app — before any hooks are used. `App.tsx` is the right place:

```tsx
import { Rovenue } from '@rovenue/react-native-sdk';

Rovenue.configure({
  apiKey: 'rov_pub_YOUR_API_KEY',
  logLevel: 'info',
});

export default function App() {
  // Foreground wiring added in the next step
  return <RootNavigator />;
}
```

<Callout type="info">
**Self-hosting?** `baseUrl` is optional and defaults to the hosted endpoint `https://api.rovenue.io`. Override it to point at your own deployment, e.g. `Rovenue.configure({ apiKey: 'rov_pub_YOUR_API_KEY', baseUrl: 'https://api.acme.com' })`. The host must use `https://` — plain `http://` is accepted only for `localhost` during local development.
</Callout>

### Types on this page

```ts
type RovenueConfig = {
  apiKey: string;      // public SDK key — prefix rov_pub_
  baseUrl?: string;    // optional — defaults to https://api.rovenue.io
  logLevel?: 'off' | 'error' | 'warn' | 'info' | 'debug' | 'trace'; // default 'warn'
  appVersion?: string; // override auto-detected version
  environment?: 'prod' | 'staging' | 'development';
};
```

| Field | Type | Description |
|-------|------|-------------|
| `apiKey` | `string` | Public SDK key from your Rovenue dashboard. Prefix `rov_pub_`. |
| `baseUrl` | `string?` | Optional. Defaults to `https://api.rovenue.io`. Override only when self-hosting (`https://`; `http://` allowed for `localhost` only). |
| `logLevel` | `string?` | Verbosity of SDK logs. Defaults to `'warn'` — turn up to `'info'`/`'debug'` locally, never ship `'debug'`/`'trace'` in production. |
| `appVersion` | `string` | Overrides the version auto-read from the bundle. |
| `environment` | `string?` | Optional environment label forwarded with requests. |

<Callout type="warn">
Call `configure` exactly once, before rendering any component that calls a Rovenue hook. Calling it more than once after initialisation is a no-op but logs a warning.
</Callout>
</Step>

<Step>
### Wire foreground signals

The SDK uses `setForeground` to manage its internal polling cadence. Wire it to React Native's `AppState` inside your root component:

```tsx
import { useEffect } from 'react';
import { AppState } from 'react-native';
import { Rovenue } from '@rovenue/react-native-sdk';

export default function App() {
  useEffect(() => {
    // Signal foreground on mount
    Rovenue.setForeground(true);

    const sub = AppState.addEventListener('change', (state) => {
      Rovenue.setForeground(state === 'active');
    });

    return () => {
      sub.remove();
    };
  }, []);

  return <RootNavigator />;
}
```

<Callout type="info">
`Rovenue.shutdown()` stops all background work (polling, in-flight refreshes). Reserve it for full app teardown — do **not** call it on every background transition. `setForeground(false)` already pauses polling when the app backgrounds.
</Callout>
</Step>

</Steps>

## Identifying users

Anonymous subscribers get a permanent `rovenueId` automatically. Call `identify` once your own auth flow completes, to link that install to your backend user:

```ts
import { Rovenue } from '@rovenue/react-native-sdk';

// After your auth flow completes:
await Rovenue.identify('user_123');

// When your user signs out:
await Rovenue.logOut();
```

`useCurrentUser()` (below) reflects the result reactively — no manual refetch needed.

<Callout type="info">
See [Identifying Users](/docs/guides/identifying-users) for the full identity model, including what happens when `identify` and `logOut` are called.
</Callout>

## React hooks

All hooks must be called from components rendered after `configure` has been called.

| Hook | Returns |
|------|---------|
| `useCurrentUser()` | `User \| null` — the identified subscriber, or `null` |
| `useEntitlement(id)` | `Entitlement \| null` — entitlement object for the given ID |
| `useEntitlements()` | `Entitlement[]` — all active entitlements |
| `useVirtualCurrencies()` | `Record<string, number>` — all virtual-currency balances |
| `useVirtualCurrency(code)` | `number` — balance for a single currency code (0 if absent) |

```ts
type User = {
  rovenueId: string;        // permanent per-install id (prefix rov_), always present
  appUserId: string | null; // your backend user id, null until identify()
};

type Entitlement = {
  id: string;                // e.g. "pro", "credits_500"
  isActive: boolean;
  productIdentifier: string;
  store: string;             // "app_store" | "play_store" | "stripe"
  expiresIso?: string;       // ISO 8601 — present for time-limited entitlements
};
```

| Field | Type | Description |
|-------|------|-------------|
| `rovenueId` | `string` | Permanent per-install id (prefix `rov_`); never changes. |
| `appUserId` | `string \| null` | Your backend user id; `null` until `identify()`. |
| `id` | `string` | Entitlement identifier configured in your dashboard. |
| `isActive` | `boolean` | `true` if the entitlement is currently active. |
| `expiresIso` | `string` | ISO 8601 expiry; present for time-limited entitlements. |

### Example — gating on an entitlement

```tsx
import { useEntitlement } from '@rovenue/react-native-sdk';

export function ProBadge() {
  const pro = useEntitlement('pro');

  if (!pro?.isActive) {
    return null;
  }

  return <Text>Pro member</Text>;
}
```

### Example — displaying virtual-currency balances

```tsx
import { useVirtualCurrency, useVirtualCurrencies } from '@rovenue/react-native-sdk';

// Show one currency by code
export function CoinsLabel() {
  const coins = useVirtualCurrency('COINS');
  return <Text>{coins} coins</Text>;
}

// Show all currencies
export function WalletSummary() {
  const balances = useVirtualCurrencies(); // Record<string, number>
  return (
    <>
      {Object.entries(balances).map(([code, amount]) => (
        <Text key={code}>{code}: {amount}</Text>
      ))}
    </>
  );
}
```

<Callout type="info">
See [Entitlements](/docs/guides/entitlements) and [Virtual Currencies](/docs/guides/credits) for the full guide on reading and reacting to subscription state.
</Callout>

## Purchases

Use `getOfferings()` to fetch products configured in your Rovenue dashboard, then `purchase(pkg)` to drive the full purchase flow. The SDK triggers the native StoreKit 2 / Play Billing sheet, validates the receipt server-side, and resolves with updated entitlements and virtual-currency balances.

```tsx
import { Rovenue, RovenueError } from '@rovenue/react-native-sdk';

const offerings = await Rovenue.getOfferings();
const pkg = offerings.current?.packages[0];

if (pkg) {
  try {
    const result = await Rovenue.purchase(pkg);
    if (result.isDeferred) {
      // Ask-to-Buy / parental-control hold — no entitlements yet. The SDK
      // reconciles it in the background; watch addChangeListener for
      // 'ENTITLEMENTS_CHANGED' to know when it resolves.
    } else {
      // result.entitlements and result.virtualCurrencies are already up to date
    }
  } catch (e) {
    if (e instanceof RovenueError && e.kind === 'PurchaseCanceled') {
      // User dismissed the store sheet — no action needed
    } else {
      throw e;
    }
  }
}
```

To re-validate all prior transactions (e.g. after a reinstall):

```ts
await Rovenue.restorePurchases();
```

```ts
type PurchaseResult = {
  entitlements: Entitlement[];
  virtualCurrencies: Record<string, number>;
  productId: string;
  storeTransactionId: string;
  isDeferred: boolean; // true for an Ask-to-Buy / parental-control hold
};
```

| Field | Type | Description |
|-------|------|-------------|
| `entitlements` | `Entitlement[]` | Updated entitlement list after the purchase. |
| `virtualCurrencies` | `Record<string, number>` | Updated virtual-currency balances after the purchase (currency code → amount). |
| `productId` | `string` | The product identifier that was purchased. |
| `storeTransactionId` | `string` | The store-side transaction ID. |
| `isDeferred` | `boolean` | `true` when the purchase is pending external approval — no entitlements are granted yet. |

<Callout type="info">
There is no `PurchaseCancelledError`/`PurchasePendingError` — every failure is a single `RovenueError` class discriminated by `.kind`, and there is no `'PurchasePending'` kind at all: as of 0.16.0, a deferred purchase does not throw; it returns normally with `isDeferred = true`. See [Reference: Errors](/docs/reference/errors) for the full 24-value `ErrorKind` taxonomy and [Processing Purchases](/docs/guides/processing-purchases) for the complete purchase API and the `StoreProduct` shape.
</Callout>

## Paywalls

`RovenuePaywallView` renders a builder paywall (see
[Placements & Paywalls](/docs/guides/placements-and-paywalls)) through the
platform's own native paywall renderer — SwiftUI on iOS, Android Views on
Android — hosted inside an Expo view, for pixel parity with the Swift and
Kotlin SDKs. Its props are unchanged from the JS renderer it replaced:

```tsx
import { RovenuePaywallView, Rovenue } from '@rovenue/react-native-sdk';

const paywall = await Rovenue.getPaywall('onboarding_end', 'en');
// Renders nothing when the paywall has no builderConfig.
<RovenuePaywallView
  paywall={paywall}
  locale="en"
  colorScheme="dark"
  onPurchaseCompleted={(result) => close()}
  onPurchaseFailed={(error) => {/* keep the paywall up */}}
  onClose={() => close()}
  onRestore={() => { /* Rovenue.restorePurchases() — omit to hide the restore button */ }}
  onUrl={(url) => {/* scheme-check, then open */}}
/>
```

<Callout type="warn">
The view only sends `paywall.placementIdentifier` across the native bridge
— it does **not** treat the `paywall` object you pass in as authoritative.
The native side re-resolves the paywall itself from the placement using the
separate `locale` prop. If you called `getPaywall('onboarding_end', 'fr')`,
pass `locale="fr"` to `RovenuePaywallView` as well — omitting it resolves
the paywall's default locale instead of the one you already fetched. Always
pass the view the same `locale` you passed to `getPaywall`.
</Callout>

The JS paywall renderer it replaced has been removed. `decodeBuilderConfig`,
`BuilderConfigModel`, and `BuilderNode` are no longer exported — the builder
config is decoded natively (Swift / Kotlin), not in JavaScript.

## Change listener

Use `Rovenue.addChangeListener` to react to server-pushed entitlement or virtual-currency updates. It returns an unsubscribe function — call it on cleanup.

```tsx
import { useEffect } from 'react';
import { Rovenue } from '@rovenue/react-native-sdk';

useEffect(() => {
  const unsub = Rovenue.addChangeListener((event) => {
    // event: 'ENTITLEMENTS_CHANGED' | 'IDENTITY_CHANGED' | 'VIRTUAL_CURRENCIES_CHANGED' | 'REMOTE_CONFIG_CHANGED'
    console.log('Rovenue change:', event);
  });

  return () => {
    unsub();
  };
}, []);
```

<Callout type="info">
See [Reacting to Changes](/docs/guides/reacting-to-changes) for a complete guide on handling live subscription events.
</Callout>
