<Step>
### Install the SDK

**Swift Package Manager** — in Xcode choose **File → Add Package Dependencies** and enter the repository URL, or add it to your `Package.swift`:

```swift
dependencies: [
  .package(url: "https://github.com/broverse/rovenue-swift.git", from: "0.16.0"),
],
targets: [
  .target(name: "YourApp", dependencies: ["Rovenue"]),
]
```

> Supported platforms: iOS 16.0+ (device and simulator) and macOS 12.0+.

**CocoaPods** — add to your `Podfile` and run `pod install`:

```ruby
pod 'Rovenue'
```
</Step>

<Step>
### Configure the SDK

Call `Rovenue.configure` once, before any SDK method is used. `AppDelegate.application(_:didFinishLaunchingWithOptions:)` is the correct place:

```swift
import UIKit
import Rovenue

@main
class AppDelegate: UIResponder, UIApplicationDelegate {

  func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {
    do {
      try Rovenue.configure(
        apiKey: "rov_pub_YOUR_API_KEY",
        logLevel: .info
      )
    } catch {
      // Only throws for a blank/malformed apiKey — a configuration
      // problem to fix before shipping, not a runtime condition to
      // recover from.
      print("Rovenue.configure failed: \(error)")
    }
    return true
  }
}
```

<Callout type="info">
**Self-hosting?** `baseUrl` is optional and defaults to the hosted endpoint `https://api.rovenue.io`. Override it to point at your own deployment, e.g. `Rovenue.configure(apiKey: "rov_pub_YOUR_API_KEY", baseUrl: "https://api.acme.com")`. The host must use `https://` — plain `http://` is accepted only for `localhost` during local development.
</Callout>

The SDK reads `CFBundleShortVersionString` from the main bundle automatically — you do not need to pass `appVersion` manually.

### Types on this page

```swift
// Swift mirror of Rovenue.configure's parameters
func configure(
  apiKey: String,
  baseUrl: String? = nil,      // optional — defaults to https://api.rovenue.io
  logLevel: LogLevel = .warn,  // .off | .error | .warn | .info | .debug | .trace
  appVersion: String? = nil,   // override auto-detected version
  environment: String? = nil
) throws
```

| Field | Type | Description |
|-------|------|-------------|
| `apiKey` | `String` | Public SDK key from your Rovenue dashboard. Prefix `rov_pub_`. |
| `baseUrl` | `String?` | Optional. Defaults to `https://api.rovenue.io`. Override only when self-hosting (`https://`; `http://` allowed for `localhost` only). |
| `logLevel` | `LogLevel` | Verbosity of SDK logs. Defaults to `.warn` — turn up to `.info`/`.debug` locally, never ship `.debug`/`.trace` in production. |
| `appVersion` | `String?` | Overrides the version auto-read from the bundle. |
| `environment` | `String?` | Optional environment label forwarded with requests. |

<Callout type="warn">
Call `configure` exactly once, before any other SDK call — the ideal location is `application(_:didFinishLaunchingWithOptions:)`. `configure` itself only throws for a blank/malformed `apiKey`; there is no `RovenueError.notConfigured` case. Calling any *other* SDK method (`Rovenue.shared.…`) before `configure` has ever run is a hard, uncatchable crash (`fatalError`) — not a throwable error on any platform. This is an ordering bug to fix at the call site, not a condition to catch. See [Calling the SDK before configure()](/docs/reference/errors#calling-the-sdk-before-configure).
</Callout>
</Step>

<Step>
### Wire foreground signals

The SDK uses `setForeground` to drive its internal polling cadence. Wire it from your `SceneDelegate`:

```swift
import UIKit
import Rovenue

class SceneDelegate: UIResponder, UIWindowSceneDelegate {

  func sceneWillEnterForeground(_ scene: UIScene) {
    Rovenue.shared.setForeground(true)
  }

  func sceneDidEnterBackground(_ scene: UIScene) {
    Rovenue.shared.setForeground(false)
  }
}
```

<Callout type="info">
If your app uses the SwiftUI `@main` lifecycle rather than a `SceneDelegate`, observe `scenePhase` from the environment and call `setForeground` from `.onChange(of: scenePhase)`.
</Callout>
</Step>

</Steps>

## Identifying users

Anonymous subscribers get a permanent `rovenueId` automatically. Call `identify` once your own auth flow completes, to link that install to your backend user:

```swift
import Rovenue

// After your auth flow completes:
try await Rovenue.shared.identify("user_123")

// When your user signs out:
try await Rovenue.shared.logOut()

let user = await Rovenue.shared.currentUser()
// user.rovenueId (always present), user.appUserId (nil until identify())
```

<Callout type="info">
See [Identifying Users](/docs/guides/identifying-users) for the full identity model, including what happens when `identify` and `logOut` are called.
</Callout>

## Purchases

Use `getOfferings()` to fetch products configured in your Rovenue dashboard, then `purchase(_:)` to drive the full StoreKit 2 purchase flow. The SDK validates the receipt server-side and resolves with updated entitlements.

```swift
let offerings = try await Rovenue.shared.getOfferings()
if let pkg = offerings.current?.packages.first {
  do {
    let result = try await Rovenue.shared.purchase(pkg)
    if result.isDeferred {
      // Ask-to-Buy / parental-control hold — no entitlements yet. The SDK
      // reconciles it in the background; watch `Rovenue.shared.changes` for
      // `.entitlementsChanged` to know when it resolves.
    } else {
      // result.entitlements and result.virtualCurrencies are already up to date
    }
  } catch let e as RovenueError {
    switch e.kind {
    case .purchaseCanceled:
      break // User dismissed the sheet — no action needed
    default:
      throw e
    }
  }
}

// Re-validate all prior transactions (e.g. after reinstall):
try await Rovenue.shared.restorePurchases()
```

```swift
// Swift mirror of PurchaseResult
struct PurchaseResult {
  var entitlements: [Entitlement]
  var virtualCurrencies: [String: Int64]
  var productId: String
  var storeTransactionId: String
  var isDeferred: Bool // true for an Ask-to-Buy / parental-control hold
}

struct Entitlement {
  var id: String
  var isActive: Bool
  var productIdentifier: String
  var store: String
  var expiresIso: String? // ISO 8601 — present for time-limited entitlements
}
```

| Field | Type | Description |
|-------|------|-------------|
| `entitlements` | `[Entitlement]` | Updated entitlement list after the purchase. |
| `virtualCurrencies` | `[String: Int64]` | Updated virtual-currency balances after the purchase (currency code → amount). |
| `productId` | `String` | The product identifier that was purchased. |
| `storeTransactionId` | `String` | The StoreKit transaction ID. |
| `isDeferred` | `Bool` | `true` when the purchase is pending external approval — no entitlements are granted yet. |

<Callout type="info">
There is no `RovenueError.purchasePending` case — as of 0.16.0, a deferred purchase (Ask-to-Buy) does not throw at all; it returns normally with `isDeferred = true`. See [Reference: Errors](/docs/reference/errors) for the full 24-value `ErrorKind` taxonomy and [Processing Purchases](/docs/guides/processing-purchases) for the complete purchase API and the `StoreProduct` shape.
</Callout>

## Paywall

`RovenuePaywallView` renders a builder paywall (see [Placements & Paywalls](/docs/guides/placements-and-paywalls)) using the shared SwiftUI paywall renderer. Resolve the placement with `getPaywall` first — the view takes the already-resolved `Paywall`, it does not take a placement identifier:

```swift
import Rovenue
import SwiftUI

if let paywall = try await Rovenue.shared.getPaywall(placementId: "onboarding") {
  // paywall is nil when the placement has no assignment — render nothing.
  RovenuePaywallView(
    paywall: paywall,
    onPurchaseCompleted: { result in /* dismiss */ },
    onPurchaseFailed: { error in /* keep the paywall up */ },
    onClose: { /* dismiss */ },
    onRestore: { Task { try? await Rovenue.shared.restorePurchases() } },
    onUrl: { url in /* scheme-check, then open */ }
  )
}
```

<Callout type="info">
See [Placements & Paywalls](/docs/guides/placements-and-paywalls) for how placements resolve to a paywall or an A/B experiment variant.
</Callout>

## Observing changes

`Rovenue.shared.changes` is an `AsyncStream` of change events. Consume it inside a long-lived `Task`:

```swift
import Rovenue

Task {
  for await event in Rovenue.shared.changes {
    // event: ChangeEvent (.entitlementsChanged | .identityChanged | .virtualCurrenciesChanged)
    print("Rovenue change:", event)
    // Update your UI or local state here
  }
}
```

Cancel the `Task` (or call `Rovenue.shared.shutdown()`) when the owning object is deallocated.

<Callout type="info">
See [Reacting to Changes](/docs/guides/reacting-to-changes) for a complete guide on handling live subscription events.
</Callout>

## Debugging

Register a log handler to receive structured log entries from the SDK. Set it up before `Rovenue.configure` to capture initialisation logs:

```swift
Rovenue.shared.setLogHandler { entry in
  print("[\(entry.level)] \(entry.message)")
}
```
