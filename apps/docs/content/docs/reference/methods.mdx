## Configuration

### `configure`

Initialise the SDK. Call this **once at app startup**, before any other Rovenue call. On React Native, pass a single config object. On Swift and Kotlin, use labelled parameters.

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `apiKey` | `string` | Yes | Your project's public API key. Prefix `rov_pub_`. |
| `baseUrl` | `string` | No | API endpoint. Defaults to the hosted endpoint `https://api.rovenue.io`; override only when self-hosting (`https://`; `http://` allowed for `localhost` only). |
| `logLevel` | `string` | No | Verbosity of SDK logs: `off` / `error` / `warn` / `info` / `debug` / `trace`. Defaults to `warn`. |
| `appVersion` | `string` | No | App version string forwarded to the server for analytics. Defaults to the value reported by the OS. |

**Returns** — `void`

**Throws** — [`InvalidApiKey`](/docs/reference/errors#error-table) if the key format is invalid at call time (a malformed prefix). The key is not validated against the server until the first network request.

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>
  <Tab value="React Native">
    ```ts
    import { Rovenue } from '@rovenue/react-native-sdk';

    Rovenue.configure({
      apiKey: 'rov_pub_…',
      logLevel: 'info',
      appVersion: '3.1.0',
      // baseUrl: 'https://api.acme.com', // optional — only when self-hosting
    });
    ```
  </Tab>
  <Tab value="Swift">
    ```swift
    import Rovenue

    Rovenue.configure(
        apiKey: "rov_pub_…",
        logLevel: .info,
        appVersion: "3.1.0"
        // baseUrl: "https://api.acme.com"  // optional — only when self-hosting
    )
    ```
  </Tab>
  <Tab value="Kotlin">
    ```kotlin
    import dev.rovenue.sdk.Rovenue

    Rovenue.configure(
        apiKey = "rov_pub_…",
        logLevel = LogLevel.INFO,
        appVersion = BuildConfig.VERSION_NAME
        // baseUrl = "https://api.acme.com"  // optional — only when self-hosting
    )
    ```
  </Tab>
</Tabs>

<Callout type="warn">
`configure` must be called before any other Rovenue method. This is a programming error to prevent by call-site ordering, not a runtime error to catch: on **iOS**, accessing the SDK before `configure` is a hard crash (`fatalError`, not a throwable error — no `catch` anywhere can intercept it); on **Android**, it throws a plain `IllegalStateException` that is not a `RovenueException`. See [Calling the SDK before `configure()`](/docs/reference/errors#calling-the-sdk-before-configure) for the full per-platform breakdown, including React Native and Flutter.
</Callout>

**See also:** [Configuring the SDK guide](/docs/guides/configuring)

### `identify`

Bind a backend user ID to the current install. Rovenue attaches the `appUserId` label to the `rovenueId` and, if that `appUserId` already exists on another install, transfers that install's purchases and credits to this device. The call is **optimistic** — local state updates immediately; the server sync completes in the background.

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `appUserId` | `string` | Yes | Your backend's stable user identifier. Must be non-empty. |

**Returns** — `void`

**Throws** — [`InvalidArgument`](/docs/reference/errors#error-table) if `appUserId` is empty or blank.

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>
  <Tab value="React Native">
    ```ts
    // After your auth flow resolves:
    await Rovenue.identify('user_123');
    ```
  </Tab>
  <Tab value="Swift">
    ```swift
    try await Rovenue.shared.identify("user_123")
    ```
  </Tab>
  <Tab value="Kotlin">
    ```kotlin
    Rovenue.shared.identify("user_123") // suspend fun
    ```
  </Tab>
</Tabs>

<Callout type="warn">
Use **opaque, unguessable** IDs — never an email address or username. Because `identify()` can transfer purchases between installs, a guessable ID is an account-takeover surface. See the [Identifying users guide](/docs/guides/identifying-users) for the recommended token-based flow.
</Callout>

**Errors:** [`InvalidArgument`](/docs/reference/errors#error-table)

React Native also exposes `useVirtualCurrencies()` and `useVirtualCurrency(code)` hooks. Swift uses `virtualCurrencyBalances() -> [String: Int64]` and `virtualCurrency(_ code:) -> Int64`. Kotlin uses `virtualCurrencyBalances(): Map<String, Long>` and `virtualCurrency(code): Long`.

## Events

### `track`

Emit a generic event to the backend. The server forwards it to any configured integrations (e.g. Meta Conversions API, TikTok Events API). The call performs the `POST /v1/events` request (retrying transient failures) and **rejects if delivery ultimately fails** — callers that don't need delivery confirmation can ignore the returned promise.

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `eventType` | `string` | Yes | The event name (e.g. `"purchase"`, `"lead"`, `"registration"`). |
| `params` | [`TrackParams`](#trackparams) | No | Optional event metadata. |

#### `TrackParams`

| Field | Type | Description |
|-------|------|-------------|
| `occurredAt` | `string` | ISO-8601 timestamp of when the event occurred. Defaults to now. |
| `subscriberId` | `string` | Override the subscriber scope. Defaults to the current user / anonymous install. |
| `productId` | `string` | Associated product identifier. |
| `amount` | `string` | Decimal string (e.g. `"9.99"`). |
| `currency` | `string` | ISO-4217 currency code (e.g. `"USD"`). |
| `eventSourceUrl` | `string` | URL of the page or screen where the event occurred. |
| `identityContext` | `object` | Identity signals for ad-platform matching. Sent as **plaintext**; the server hashes them before forwarding to integrations. Fields: `email`, `externalId`, `phone`, `ip`, `userAgent`, `firstName`, `lastName`, `city`, `countryCode`. |

**Returns** — `void`

**Throws** — rejects with a `RovenueError` if the event can't be delivered after retries.

<Callout type="info">
The typed `track(eventType, params)` signature is the React Native API. On **Swift and Kotlin**, `track(envelopeJson:)` takes a pre-built camelCase JSON envelope string using the same field names (`eventType` and `occurredAt` required). The SDK stamps the wire `version` and a stable `eventId` for you.
</Callout>

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>
  <Tab value="React Native">
    ```ts
    import { Rovenue } from '@rovenue/react-native-sdk';

    // Minimal — event type only:
    await Rovenue.track('lead');

    // With params:
    await Rovenue.track('purchase', {
      amount: '9.99',
      currency: 'USD',
      productId: 'com.example.pro_monthly',
    });

    // With identity context for ad-platform matching:
    await Rovenue.track('registration', {
      identityContext: {
        email: 'user@example.com',
        phone: '+15551234567',
      },
    });
    ```
  </Tab>
  <Tab value="Swift">
    ```swift
    import Foundation

    // Swift takes a pre-built camelCase JSON envelope string.
    func envelope(_ fields: [String: String]) -> String {
        let data = try! JSONSerialization.data(withJSONObject: fields)
        return String(data: data, encoding: .utf8)!
    }
    let now = ISO8601DateFormatter().string(from: Date())

    // Minimal:
    try await Rovenue.shared.track(envelopeJson: envelope([
        "eventType": "lead", "occurredAt": now,
    ]))

    // With params:
    try await Rovenue.shared.track(envelopeJson: envelope([
        "eventType": "purchase",
        "occurredAt": now,
        "amount": "9.99",
        "currency": "USD",
        "productId": "com.example.pro_monthly",
    ]))
    ```
  </Tab>
  <Tab value="Kotlin">
    ```kotlin
    import org.json.JSONObject
    import java.time.Instant

    // Kotlin takes a pre-built camelCase JSON envelope string.
    // track() is a suspend fun — call it from a coroutine.
    val now = Instant.now().toString()

    // Minimal:
    Rovenue.shared.track(
        JSONObject(mapOf("eventType" to "lead", "occurredAt" to now)).toString()
    )

    // With params:
    Rovenue.shared.track(
        JSONObject(mapOf(
            "eventType" to "purchase",
            "occurredAt" to now,
            "amount" to "9.99",
            "currency" to "USD",
            "productId" to "com.example.pro_monthly",
        )).toString()
    )
    ```
  </Tab>
</Tabs>

<Callout type="info">
`track()` is a client-side convenience wrapper around `POST /v1/events`. For server-side event ingestion (e.g. from your backend after a payment processor webhook), call the HTTP endpoint directly with your secret API key.
</Callout>

### `purchase`

Trigger a native store sheet for the given package. The SDK handles the full purchase lifecycle: StoreKit 2 on iOS, Play Billing on Android, server-side receipt validation. Resolves with updated entitlements and credit balance — no additional polling needed.

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `pkg` | [`Package`](/docs/reference/types#package) | Yes | A package from [`getOfferings()`](#getofferings). |

> **Android:** Kotlin requires the current `Activity` as the first argument — `purchase(activity, pkg)`. iOS (Swift) and React Native take only the package.

**Returns**

```ts
type PurchaseResult = {
  entitlements: Entitlement[];              // full set of active entitlements after the purchase
  virtualCurrencies: Record<string, number>; // virtual-currency balances after the purchase
  productId: string;                        // the store product ID purchased
  storeTransactionId: string;               // StoreKit 2 transaction ID or Play Billing order ID
  isDeferred: boolean;                      // true for Ask-to-Buy / parental-control holds — see below
};
```

→ Full type reference: [`PurchaseResult`](/docs/reference/types#purchaseresult)

<Callout type="warn">
**Ask-to-Buy / parental-control holds are not an error.** `purchase()` does not throw
for a pending approval — it resolves normally with `isDeferred: true` (and empty
`entitlements` / `storeTransactionId`, since nothing has been granted yet). See
[Handling a deferred purchase](#handling-a-deferred-purchase) below. Do not write a
catch branch for this condition; there is no `kind` for it.
</Callout>

**Throws** — see table below

| Error | When it fires |
|-------|--------------|
| [`PurchaseCanceled`](/docs/reference/errors#error-table) | User dismissed the store sheet without completing payment |
| [`ProductNotAvailable`](/docs/reference/errors#error-table) | The product is not available in the user's storefront |
| [`StoreProblem`](/docs/reference/errors#error-table) | The store returned a non-specific error (e.g. billing issue) |
| [`ReceiptInvalid`](/docs/reference/errors#error-table) | Server-side receipt validation failed |

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>
  <Tab value="React Native">
    ```ts
    import { Rovenue, RovenueError } from '@rovenue/react-native-sdk';

    const offerings = await Rovenue.getOfferings();
    const pkg = offerings.current?.packages[0];

    if (pkg) {
      try {
        const result = await Rovenue.purchase(pkg);
        if (result.isDeferred) {
          // Ask-to-Buy — tell the user to wait for approval (see below)
        } else {
          console.log('Purchase succeeded:', result.productId);
          // result.entitlements and result.virtualCurrencies are already up to date
        }
      } catch (e) {
        if (!(e instanceof RovenueError)) throw e;
    ```

#### Handling a deferred purchase

There is no purchase-specific notification for when a deferred (Ask-to-Buy) purchase
resolves — the SDK reconciles it in the background and reports the result the same way
as any other entitlement change. Listen for `ChangeEvent`'s entitlements-changed value
on each platform's [change stream](#change-stream): RN
`Rovenue.addChangeListener((event) => { if (event === 'ENTITLEMENTS_CHANGED') { /* re-check entitlements */ } })`;
Swift/Kotlin — collect `Rovenue.shared.changes` and match `.entitlementsChanged` /
`ChangeEvent.ENTITLEMENTS_CHANGED`.

### `getPaywall`

Resolve a placement identifier into the paywall the current subscriber should see — either a direct assignment or the winning variant of a client-drawn `PAYWALL` experiment.

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `placementId` | `string` | Yes | The placement identifier configured in the dashboard. |
| `locale` | `string` | No | BCP-47 tag used to pick the paywall's localised text. Omitted means the server's default. Resolution matches by **language**, not the exact tag. |

**Returns** — `Promise<Paywall | null>`. `null` means the placement resolved to nothing (retired, `target: none`, or an unknown identifier) — that is **not** an error, and an unknown placement never produces a 404.

The resolved `Paywall` carries:

| Field | Type | Description |
|-------|------|-------------|
| `placementIdentifier` | `string` | The identifier you asked for. |
| `placementRevision` | `number` | Revision of the placement configuration this resolution came from. |
| `paywallIdentifier` | `string \| null` | Identifier of the resolved paywall. |
| `paywallName` | `string \| null` | Human-readable paywall name. |
| `configFormatVersion` | `number` | Format version of the paywall payload. |
| `remoteConfig` | `Record<string, unknown> \| null` | Parsed remote-config payload. `null` when there is none for the resolved locale, or the JSON does not parse into an object — a broken payload never fails the call. |
| `remoteConfigLocale` | `string \| null` | Locale the remote-config text was resolved for. |
| `builderConfig` | `Record<string, unknown> \| null` | Parsed builder component tree. `null` for remote-config-only paywalls, or when the JSON does not parse into an object. |
| `offering` | `Offering \| null` | The offering bound to this paywall, already hydrated with store products. |
| `presentedContext` | `PresentedContext \| null` | Attribution snapshot (`placementId`, `paywallId`, `variantId`, `experimentKey`, `revision`). `logPaywallShown` / `logPaywallClosed` are built from this. |
| `servedFromFallback` | `boolean` | `true` only when this resolution came from the bundled fallback file. |

**Resolution order** — network first; on a connectivity failure only (`NetworkUnavailable` / `Timeout`) the last cached response for that placement is re-resolved, and if there is no cached response either, the bundled fallback file (see [`setFallbackPlacements`](#setfallbackplacements)) is consulted. Auth and server errors are *not* absorbed this way: they propagate. Cache always beats fallback.

**Side effects** — two, both worth knowing:

1. When the placement resolves through a `PAYWALL` experiment, the variant draw happens **client-side** and deterministically off the subscriber's `rovenueId`, and the SDK then fires a best-effort `POST /v1/experiments/{id}/expose` exposure beacon on a background thread. Failures are logged and swallowed; the paywall you already got back is unaffected. Merely calling `getPaywall` therefore records an exposure — do not call it speculatively for a paywall you will not show.
2. The resolved paywall's attribution snapshot is stamped into SDK state, so the next receipt POST carries it as `presentedContext`. Purchase attribution follows the most recent `getPaywall` call.

**Throws** — [`NetworkUnavailable`](/docs/reference/errors#error-table), [`Timeout`](/docs/reference/errors#error-table) (both only when neither cache nor fallback could answer), [`InvalidApiKey`](/docs/reference/errors#error-table), [`ServerError`](/docs/reference/errors#error-table)

## Remote Config

Feature flags and experiment assignments, evaluated server-side for the current subscriber and cached locally.

### Method summary

| Method | Signature (RN) | Returns | Throws |
|--------|---------------|---------|--------|
| `refreshRemoteConfig` | `refreshRemoteConfig()` | `Promise<void>` | [`NetworkUnavailable`](/docs/reference/errors#error-table), [`Timeout`](/docs/reference/errors#error-table), [`RateLimited`](/docs/reference/errors#error-table), [`InvalidApiKey`](/docs/reference/errors#error-table), [`ServerError`](/docs/reference/errors#error-table) |

| `getFlag` | `getFlag(key, fallback)` | `Promise<T>` | — |
| `getExperiment` | `getExperiment(key)` | `Promise<ExperimentAssignment \| null>` | — |
| `getExperiments` | `getExperiments()` | `Promise<ExperimentAssignment[]>` | — |

**Cache vs. network:** only `refreshRemoteConfig()` performs a network round-trip. The four read methods resolve from the local cache — they are `async` (the value crosses the native bridge) but they never fetch, so they work offline and never throw on a malformed payload; each degrades to its documented fallback instead.

React Native also exposes reactive hooks: `useRemoteConfig()`, `useFlag(key, fallback)` and `useExperiment(key)`. They read the same local cache synchronously, prime it on first mount, and re-render on `REMOTE_CONFIG_CHANGED`.

Swift and Kotlin do not have a single `getFlag` — they expose typed getters instead: `remoteConfigBool`, `remoteConfigString`, `remoteConfigInt`, `remoteConfigDouble` and `remoteConfigJson` (Swift: `remoteConfigJSON`), plus `remoteConfigKeys()`. Nor do they have a struct-returning `getRemoteConfig`: `remoteConfigAllJson()` (Swift: `remoteConfigAllJSON()`) returns the whole bundle as a raw JSON string.

On React Native, structured error detail travels inside the native error `message` as a JSON envelope (the Expo JSI bridge forwards only `code` and `message`); the SDK unpacks it for you into `RovenueError.serverCode`, `.httpStatus`, `.isRetryable` and `.data.retryAfter`, so a `RateLimited` refresh still tells you how long to wait.

## Subscriber Attributes

Attach arbitrary key/value metadata to the current subscriber — plus a set of reserved, `$`-prefixed keys that map to first-class fields server-side and drive the integrations.

### Method summary

| Method | Signature (RN) | Returns | Throws |
|--------|---------------|---------|--------|
| `setAttributes` | `setAttributes(attributes)` | `Promise<void>` | [`Storage`](/docs/reference/errors#error-table) |
| `setEmail` | `setEmail(email)` | `Promise<void>` | [`Storage`](/docs/reference/errors#error-table) |
| `setDisplayName` | `setDisplayName(name)` | `Promise<void>` | [`Storage`](/docs/reference/errors#error-table) |
| `setPhoneNumber` | `setPhoneNumber(phone)` | `Promise<void>` | [`Storage`](/docs/reference/errors#error-table) |
| `setPushToken` | `setPushToken(token)` | `Promise<void>` | [`Storage`](/docs/reference/errors#error-table) |
| `flushAttributes` | `flushAttributes()` | `Promise<number>` | [`NetworkUnavailable`](/docs/reference/errors#error-table), [`Timeout`](/docs/reference/errors#error-table), [`ServerError`](/docs/reference/errors#error-table) |

**Write model — read this before using any of them.** Every setter is a **buffered local write**. The returned promise resolves once the mutation has been written to the on-device buffer, *not* once the server has it. A background dispatcher syncs the buffer every 30 seconds, and again when the app comes to the foreground; [`flushAttributes`](#flushattributes) forces it early. So a resolved `setEmail()` means "durably queued", never "the server knows".

`shutdown()` does not flush the buffer. If you tear the SDK down and it matters that pending mutations land, call `flushAttributes()` first.

Passing `null` as a value **deletes** the key rather than storing an empty value. The four named setters are thin wrappers over `setAttributes` for the most common reserved keys.

---

### `setAttributes`

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `attributes` | `Record<string, string \| null>` | Yes | Key → value. A `null` value deletes that key. Keys prefixed with `$` are reserved and map to first-class server-side fields. |

**Returns** — `Promise<void>` (resolves on the local buffered write — see the write model above)

**Throws** — [`Storage`](/docs/reference/errors#error-table) if the local buffer cannot be written

    ```ts
      plan_interest: 'annual',
    ```

## Change Stream

Subscribe to real-time state change notifications from the SDK. The SDK fires an event whenever the entitlement cache, identity, virtual-currency balances, or remote config are updated. React to these events to keep your UI in sync without polling.

| Method / Property | Platform | Description |
|-------------------|----------|-------------|
| `addChangeListener(handler)` | React Native | Register a callback; returns an unsubscribe function. |
| `changes` | Swift | `AsyncStream<ChangeEvent>` — iterate with `for await`. |
| `changes` | Kotlin | `SharedFlow<ChangeEvent>` — collect with `.onEach { }.launchIn(scope)`. |

The [`ChangeEvent`](/docs/reference/types#changeevent) values (shown as the React Native
string value — see [`ChangeEvent`](/docs/reference/types#changeevent) for the exact
Swift case / Kotlin constant spelling of each):

| Value (RN) | When it fires |
|-------|--------------|
| `'ENTITLEMENTS_CHANGED'` | After any entitlement cache refresh (purchase, `refreshEntitlements()`, foreground sync). |
| `'IDENTITY_CHANGED'` | After `identify()` succeeds or `logOut()` resets the user. |
| `'VIRTUAL_CURRENCIES_CHANGED'` | After `refreshVirtualCurrencies()` or a server-side grant/spend that updates the cache. |
| `'REMOTE_CONFIG_CHANGED'` | After every successful [`refreshRemoteConfig()`](#refreshremoteconfig). The SDK does not diff the payload, so this also fires when the refresh returned identical values. |

→ Full type reference: [`ChangeEvent`](/docs/reference/types#changeevent)

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>
  <Tab value="React Native">
    ```ts

      switch (event) {
        case 'ENTITLEMENTS_CHANGED':
          // Re-read entitlements and update gated UI
          break;
        case 'IDENTITY_CHANGED':
          // User identity has changed — re-read currentUser()
          break;
        case 'VIRTUAL_CURRENCIES_CHANGED':
          // Re-read virtualCurrencies() and update the balance display
          break;
        case 'REMOTE_CONFIG_CHANGED':
          // Re-read your flags/experiments
          break;
      }
    });

    // When your component unmounts:
    unsub();
    ```
  </Tab>
  <Tab value="Swift">
    ```swift

        case .virtualCurrenciesChanged:
            // Re-read virtualCurrencyBalances() and update the balance display
        case .remoteConfigChanged:
            // Re-read your flags/experiments
        }
    }
    ```
  </Tab>
  <Tab value="Kotlin">

### `claimFunnelToken`

| [`FunnelTokenExpired`](/docs/reference/errors#error-table) | The token has passed its expiry window |
| [`FunnelTokenAlreadyClaimed`](/docs/reference/errors#error-table) | The token was already consumed by a previous install |

### `claimInstall`

Recover a prior funnel session deterministically from caller-supplied install context (e.g. an Android Install Referrer token) and claim it. Returns a `FunnelClaimResult` if a prior funnel session is matched, or `null` if no match can be recovered. This is deterministic — it does **not** use device fingerprinting. Call this once on first launch, immediately after `configure`.

On **iOS**, when no explicit token is available, recovery falls back to a deterministic server-side **IP match within a 1-hour window** — no device fingerprinting is used. For clipboard-based recovery on iOS, see [`claimFromClipboard`](#claimfromclipboard).

**Params** — all optional on React Native; on native Swift and Kotlin every field must
be supplied (see the callout below).

On **React Native's Android bridge specifically**, the SDK auto-collects `platform`,
`locale`, `timezone`, `screenDims`, `deviceModel`, and the Google Play Install Referrer
from the native layer — pass any field only to override the auto-collected value. On
**React Native's iOS bridge**, callers still supply context explicitly (auto-collection
for iOS will land in a later release).

<Callout type="warn">
**Native Swift and Kotlin have no auto-collection at all.** The auto-collection above is
a convenience built into the React Native Android bridge specifically — the underlying
`packages/sdk-swift` and `packages/sdk-kotlin` façades take one `ClaimInstallParams`
struct with no default values, so a native caller must always compute and supply every
field itself (see the Swift/Kotlin tabs below for how to derive them).
</Callout>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | `"ios" \| "android"` | No (RN) / Yes (Swift, Kotlin) | Platform of the current install. Auto-collected on RN's Android bridge. |
| `locale` | `string` | No (RN) / Yes (Swift, Kotlin) | IETF BCP 47 locale tag (e.g. `"en-US"`). Auto-collected on RN's Android bridge. |
| `timezone` | `string` | No (RN) / Yes (Swift, Kotlin) | IANA timezone identifier (e.g. `"America/New_York"`). Auto-collected on RN's Android bridge. |
| `screenDims` | `string` | No (RN) / Yes (Swift, Kotlin) | Screen dimensions in pixels, formatted `"WIDTHxHEIGHT"` (e.g. `"1080x2400"`) — a plain string, not a width/height object. Auto-collected on RN's Android bridge. |
| `deviceModel` | `string \| null` | No | Device model string (e.g. `"iPhone16,1"`). Auto-collected on RN's Android bridge; pass `null` on native Swift/Kotlin if you have nothing to send. |
| `installReferrer` | `string \| null` | No | Android Install Referrer string from the Play Store; auto-collected on RN's Android bridge, `null` on iOS and on native Kotlin unless you read it yourself. |

**Returns** — [`FunnelClaimResult`](/docs/reference/types#funnelclaimresult) `| null` (`null` means no prior funnel session was matched)

**Throws** — nothing

<Tabs groupId="platform" persist items={['React Native', 'Swift', 'Kotlin']}>

### `resolveFunnelClaim`

**React Native only.** Runs the no-gesture, deterministic first-launch attribution chain once per install and returns the result. The chain is:

1. **Direct deep link** — if a URL is supplied (or the app was cold-started from one), extract and claim the embedded funnel token via `claimFromUrl`.
2. **Platform deferred match** — if step 1 yields no result, call `claimInstall`, which on Android queries the Google Play Install Referrer and on iOS performs a server-side IP match within a 1-hour window. No device fingerprinting is used at any step.

Once a claim has succeeded for this install the method short-circuits immediately and returns the cached result without a network round-trip.

Internal claim errors (network failures, token not found, etc.) are treated as "unresolved" rather than thrown — the method never throws on its own. Resolved claims are also delivered to any listener registered with [`addFunnelClaimListener`](#addfunnelclaimlistener).

**Params** — all optional

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `url` | `string` | No | The URL the app was launched with (e.g. from `Linking.getInitialURL()`). Pass `undefined` to skip the deep-link step. |

**Returns** — [`FunnelClaimResult`](/docs/reference/types#funnelclaimresult) `| null` (`null` when neither step resolves a claim)

**Throws** — nothing

```ts
import { Rovenue } from '@rovenue/react-native-sdk';
import * as Linking from 'expo-linking';

// Recommended first-launch flow — call once after Rovenue.configure():
const url = await Linking.getInitialURL();
const result = await Rovenue.resolveFunnelClaim({ url: url ?? undefined });

if (result) {
  // Claim resolved deterministically — apply funnel-specific onboarding.
  console.log('Funnel claim resolved for subscriber:', result.subscriberId);
} else {
  // No deterministic match. Try gesture-gated fallbacks in sequence:

  // 1. iOS clipboard (show a "Continue" button, then on tap):
  //    const clipResult = await Rovenue.claimFromClipboard();

  // 2. Email magic-link (show an email field, then on submit):
  //    await Rovenue.claimViaEmail(email);
  //    // Result arrives via addFunnelClaimListener when the link is tapped.
}
```

### `claimFromClipboard`

**React Native only, and iOS only within that.** There is no `claimFromClipboard` on
the native Swift or Kotlin SDKs — `Rovenue.shared` has no equivalent method on either
platform (confirmed against `packages/sdk-swift/Sources/Rovenue/Rovenue.swift` and
`packages/sdk-kotlin/.../Rovenue.kt`; grepping both trees for `claimFromClipboard`
returns nothing outside the RN package). It exists purely as a convenience in
`@rovenue/react-native-sdk`, implemented on top of the standard claim flow: it reads a
`rovenue-funnel:<token>` marker placed on the clipboard by the web funnel, extracts the
token, calls the same `claimFunnelToken` every platform already has, then clears the
marker from the clipboard so it can't be re-claimed or leaked. Returns a
`FunnelClaimResult` if the marker is present and matched, or `null` on Android or when
no marker is found.

**Call from a user-gesture handler** (e.g. a "Continue" tap on your first onboarding
screen) — iOS shows a one-time paste-access banner on the clipboard read.

**On native Swift or Kotlin, there is no built-in equivalent — replicate it yourself**
using [`claimFunnelToken`](#claimfunneltoken): read the clipboard string (`UIPasteboard.general.string`
on iOS; there's no Android equivalent, since the RN version is also a no-op there),
check it starts with `"rovenue-funnel:"`, strip the prefix to get the token, and call
`claimFunnelToken(token)`. Clear the clipboard afterward if you want the same
can't-be-reclaimed behavior the RN version has.

**Params** — none

**Returns** — [`FunnelClaimResult`](/docs/reference/types#funnelclaimresult) `| null` (`null` on Android, or when no `rovenue-funnel:` marker is present)

**Throws** — nothing

```ts
import { Rovenue } from '@rovenue/react-native-sdk';

// Call from a user-gesture handler (e.g. a "Continue" button press):
const result = await Rovenue.claimFromClipboard();

if (result) {
  console.log('Clipboard funnel claim resolved:', result.subscriberId);
}
// Returns null on Android or when no rovenue-funnel: marker is present.
```

### `claimFromUrl`

Parse and claim a funnel token from any URL the app receives via a Universal Link, App Link, or custom-scheme deep link. Call this whenever the OS hands your app a URL — it is safe to pass **any** URL; non-funnel URLs return `null` immediately without a network request.

Recognized URL shapes:

| Shape | Example |
|-------|---------|
| Universal Link / App Link path segment | `https://funnels.example.com/funnels/open/<token>` |
| Query parameter (any host) | `https://example.com/promo?rovenue_funnel_token=<token>` |
| `token=` on the `onboarding-complete` deep link | `myapp://onboarding-complete?token=<token>` |

**Params**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `url` | `string` | Yes | Any URL the app received from the OS. Non-funnel URLs are ignored and resolve to `null`. |

**Returns** — `Promise<`[`FunnelClaimResult`](/docs/reference/types#funnelclaimresult)` | null>` (`null` for URLs that contain no recognizable funnel token — no network call is made)

**Throws** — funnel claim errors when a **recognized** token fails server-side: [`FunnelTokenNotFound`](/docs/reference/errors#error-table), [`FunnelTokenExpired`](/docs/reference/errors#error-table), or [`FunnelTokenAlreadyClaimed`](/docs/reference/errors#error-table). Non-funnel URLs resolve `null` and never throw — so always wrap the call (a fire-and-forget handler should `.catch`).

This is a React Native helper. On Swift/Kotlin, parse the token from the incoming URL yourself and call [`claimFunnelToken`](#claimfunneltoken).

```ts
import { Rovenue } from '@rovenue/react-native-sdk';
import * as Linking from 'expo-linking';

// Warm start — app already open when the link is tapped:
Linking.addEventListener('url', ({ url }) => {
  Rovenue.claimFromUrl(url).catch(() => {
    // expired / already-claimed / not-found — recover via email or ignore
  });
});

// Cold start — app launched via the link:
const initial = await Linking.getInitialURL();
if (initial) {
  try {
    await Rovenue.claimFromUrl(initial);
  } catch {
    // recognized token failed server-side — fall back to email recovery
  }
}
```

<Callout type="info">
The OS-level deep-link configuration — iOS Associated Domains (for the funnel Universal Link domain), Android App Links intent filter, and any custom URL scheme — lives in the **consuming app**, not the SDK. See your platform's documentation for setup instructions.
</Callout>

When a funnel token is found and successfully claimed, the result is delivered via [`addFunnelClaimListener`](#addfunnelclaimlistener). The return value of `claimFromUrl` itself is `null` for non-funnel URLs and the [`FunnelClaimResult`](/docs/reference/types#funnelclaimresult) for matched ones.
